二、消息事件系统 (XMsgEvent)

2.1 通信协议格式

sequenceDiagram
    participant S as 发送方
    participant N as 网络
    participant R as 接收方

    S->>S: 1. 构造XMsgHead(PB)和body(PB)
    S->>S: 2. 打包: [head_size(int32)][head_data(PB)][body_data]
    S->>N: 3. bufferevent_write 发送

    N->>R: 数据到达
    R->>R: 4. RecvMsg() 分3步接收
    R->>R: 5. Step1: 读4字节 head_size
    R->>R: 6. Step2: 读head_size字节 XMsgHead PB
    R->>R: 7. Step3: 读head.body_size()字节 body
    R->>R: 8. ReadCB(msg_type) 派发

2.2 消息派发机制

classDiagram
    class XMsgEvent {
        +static map~MsgType, MsgCBFunc~ msg_cb_
        +void ReadCB()
        +void RegCB(MsgType, MsgCBFunc)
        +bool RecvMsg(XMsgHead*, XMsg*)
        +bool SendMsg(XMsgHead*, XMsg*)
        +bool SendMsg(MsgType, Message*)
    }

    note for XMsgEvent "ReadCB() main loop:\nwhile(RecvMsg()) {\n  GetMsg()\n  find msg_cb_[msg_type]\n  call callback\n  Clear()\n}"

消息注册： 每个Handle类通过静态方法 RegMsgCallback() 注册消息类型 → 成员函数的映射。
消息派发： XMsgEvent::ReadCB() 循环调用 RecvMsg() 解析协议，根据 msg_type 在全局静态 map 中查找回调函数并调用。
SendMsg 重载： 提供3种发送方式：SendMsg(head, msg_data)、SendMsg(head, pb_message)、SendMsg(msg_type, pb_message)，最终统一走3步打包流程。

已知Bug (issue.txt): XMsg::Alloc() 使用 new char[] 但 Clear() 使用 delete 而非 delete[]，导致内存泄漏。pb_head_ 内存未被释放。

CXThread 主循环 (Main())： 使用 event_base_loop(EVLOOP_NONBLOCK) 处理libevent事件 + sleep(1ms) 忙等的模式。这种设计是为了在没有事件时也能及时响应其他任务。
线程激活： 通过 socketpair/pipe 的 notify 机制，Activate() 写入字节触发 libevent 事件回调，然后在回调中 AddTask 加入任务队列。
任务分发： CXThreadPool::Dispatch() 使用 round-robin 轮询策略选择线程。
线程池创建： XThreadPoolFactory::Create() 在Windows上调用 WSAStartup，Linux上忽略 SIGPIPE 信号。

已知Bug: CXThread::Main() 使用忙等(sleep 1ms)消耗CPU；is_exit_ 非原子类型且未加锁，线程安全风险。

5.2 事件回调机制

EventCB() 处理 4 种bufferevent事件：
- BEV_EVENT_CONNECTED：设置 is_connected_=true，打印SSL证书信息(SSL模式下)，调用虚函数 ConnectedCB()
- BEV_EVENT_ERROR：获取socket错误码，调用 Close() 清理
- BEV_EVENT_TIMEOUT：直接调用 Close()
- BEV_EVENT_EOF：对端关闭连接，调用 Close()

Close() 流程：加锁 → bufferevent_free → 关闭socket → 清理msg数据 → 释放ssl对象 → 检查auto_delete决定是否delete this

定时器：SetTimer(ms) 通过 libevent event_new(-1) 创建定时事件，TimerCB() 可被子类重载。ClearTimer() 用于清理定时器。

6.2 各工具模块详解

XAES/CXAES - AES加密：
- 使用OpenSSL的AES_ECB模式，PKCS7填充
- SetKey支持128/192/256位(16/24/32字节)，不足自动补0
- Encrypt/Decrypt以16字节块为单位处理数据
- Drop()清理对象内存

XMutex - RAII包装器：
- 构造函数调用 mutex->lock()，析构函数调用 mutex->unlock()
- 调试模式(is_debug=true)打印锁/解锁事件及计数器
- 通过宏 XMUTEX(s) 简化调用，同时传入变量名作为调试标识

Base64编解码：
- 使用OpenSSL BIO链：BIO_f_base64() → BIO_s_mem()
- Base64Encode: BIO_push(b64, mem) → BIO_write → BIO_flush → 读取结果
- Base64Decode: BIO_push(b64, mem) → 写入数据 → BIO_read 解码

XMD5：
- XMD5(): 直接封装OpenSSL的MD5()函数，输出16字节
- XMD5_base64(): MD5计算后经Base64编码为24字节字符串
- 用途：密码哈希存储、文件切片校验

文件系统工具：
- GetDirList(): Windows用_finddata_t/_findfirst，Linux用dirent/opendir，返回文件列表
- GetDirSize(): 递归遍历目录累加文件大小
- GetDiskSize(): Windows用GetDiskFreeSpaceExA，Linux用statfs
- GetDirData(): 读取文件内容为string
- XGetHostByName(): 封装gethostbyname()，用于域名→IP解析（服务发现的基础）

8.2 注册中心业务逻辑

sequenceDiagram
    participant S as 微服务
    participant RC as XRegisterClient
    participant RS as XRegisterServer
    participant RM as XRegisterHandle

    Note over S: 服务启动
    S->>RC: RegisterServer("dir", 20011, "127.0.0.1")
    RC->>RC: 保存服务名/IP/端口
    RC->>RC: 设置自动重连 + 心跳定时器(3s)
    RC-->>RS: Connect()
    RS-->>RC: BEV_EVENT_CONNECTED
    RC->>RS: ConnectedCB → MSG_REGISTER_REQ
    RS->>RM: RegisterReq()
    RM->>RM: 验证name/ip/port
    RM->>RM: 检查重复 → 加入XServiceMap
    RM-->>RC: MSG_REGISTER_RES

    Note over S: 服务发现(网关)
    RC->>RS: GetServiceReq(NULL) → type=ALL
    RS->>RM: GetServiceReq()
    RM->>RM: 从service_map查找
    RM-->>RC: MSG_GET_SERVICE_RES(全部服务列表)
    RC->>RC: GetServiceRes(): 更新缓存 + 持久化到磁盘

    Note over S: 心跳保活
    RC->>RS: MSG_HEART_REQ(每3s)

服务注册流程： 各微服务启动时调用 XRegisterClient::RegisterServer()，自动连接注册中心并发送 MSG_REGISTER_REQ 注册自身信息。服务信息包含：name(服务名)、ip、port、is_find(是否对外开放)。

服务发现流程： 网关通过 XRegisterClient::GetServiceReq() 获取全局服务列表，注册中心返回 XServiceMap (map<string, XServiceList>)。客户端缓存到内存并持久化到磁盘(register_*.cache)用于容灾。

XRegisterHandle::RegisterReq()： 验证服务信息的合法性 → 检查是否重复注册 → 添加到 XServiceMap → 返回 MSG_REGISTER_RES
XRegisterHandle::GetServiceReq()： 根据请求类型(ALL/ONE)返回全部或指定服务列表
磁盘缓存： GetServiceRes() 每次收到响应都将 service_map 序列化到 "register_{name}{ip}{port}.cache" 文件

注意： XRegisterClient 使用静态指针+手动new管理单例(非局部static)，需要保证 Get() 的线程安全。心跳通过 TimerCB 每 3s 发送 MSG_HEART_REQ。

9.2 配置中心业务逻辑

ConfigDao (单例 DAO)：

- Init(): 创建 LXMysql 连接，设置自动重连+3秒超时，通过 InputDBConfig() 加载数据库配置
- Install(): 创建 xms_config 表(id, service_ip, service_port, private_pb)
- SaveConfig(XConfig): 调用 LXMysql::InsertBin() 将配置存入数据库
- LoadConfig(ip, port): 按 ip+port 查询配置记录
- LoadAllConfig(page, count): 分页查询所有配置
- DeleteConfig(ip, port): 按条件删除配置记录

XConfigHandle 消息处理 (PB → DAO → SendMsg)：

- SaveConfig(): 解析 XConfig → client_ip回退 → ConfigDao::SaveConfig() → 返回 MSG_SAVE_CONFIG_RES
- LoadConfig(): 解析 XLoadConfigReq → ConfigDao::LoadConfig() → 返回 MSG_LOAD_CONFIG_RES
- DeleteConfig(): 解析 XLoadConfigReq → ConfigDao::DeleteConfig() → 返回 MSG_DEL_CONFIG_RES
- LoadAllConfig(): 解析 XLoadAllConfigReq(含page/page_count) → ConfigDao::LoadAllConfig() → 返回 MSG_LOAD_ALL_CONFIG_RES

XConfigClient 详解

StartGetConf() 双版本：
- 版本1(有ConfigTimerCB回调): 先从注册中心获取配置中心IP → 连接 → 定时获取配置
- 版本2(直接指定配置中心): 连接配置中心 → 等待连接成功 → LoadConfig → 设置定时器(3s)

动态Proto加载： XConfigClient::LoadProto() 使用 protobuf 的 DiskSourceTree + Importer + DynamicMessageFactory 实现动态解析 .proto 文件并生成 Message 对象。支持指定 class_name 或使用第一个 message 类型。

配置缓存： 本地缓存到 "{port}_conf.cache" 文件，启动时自动加载，网络不可用时作为容灾配置。

GetConfig()： 从 conf_map(ip_port→XConfig) 中查询指定服务的配置，支持超时等待(默认100ms)。

GetInt/GetBool/GetString： 使用 protobuf 反射 API 从 cur_service_conf Message 中动态读取字段值。

密码与Token管理

Login() 流程： 客户端发送MD5(password) → 服务端查询 xms_auth 表验证用户名密码 → 生成UUID token → 存入 xms_token 表(含过期时间) → 返回 token+expired_time

CheckToken() 流程： 服务端按 token 查询 xms_token 表 → 返回 username+rolename → 匹配header中的用户信息

AddUser()： 客户端MD5编码密码后发送 → 服务端插入 xms_auth 表

ChangePassword()： 更新 xms_auth 表密码字段

XUploadHandle 服务端详解

- UploadFileReq()： 接收 XFileInfo → 构建存储路径 → XNewDir() 创建目录 → 打开 ofstream 准备写入 → 返回结果
- SendSliceReq()： 验证 head->md5() 与数据的 XMD5_base64 是否一致(完整性校验) → ofs.write() 写入本地文件 → 返回结果
- UploadFileEndReq()： 关闭 ofstream → 构造 .info_{filename} 信息文件(序列化 XFileInfo) → 返回结果
- 每个 XUploadHandle 对象只处理一个文件(构造时设 set_timer_ms(100) 用于进度跟踪)

XUploadClient 客户端详解

- set_file()： 打开本地文件 → 读取所有切片并计算每个切片的MD5(用于秒传) → 所有切片MD5拼接后生成文件MD5 → 若加密则补齐16字节倍数 → 初始化AES密钥
- ConnectedCB()： 连接建立后立即发送 UPLOAD_FILE_REQ(过滤password字段)
- SendSlice()： 读取切片 → 可选AES加密 → 设置MD5校验头 → 发送 SEND_SLICE_REQ
- UploadFileEndRes()： 通知XFileManager::UploadEnd() → 刷新目录 → 清除定时器 → Close()
- TimerCB() (每100ms)： 通过 bufferevent 的 send_data_size() - BufferSize() 计算已发送字节，更新进度
- 切片大小默认 10MB (FILE_SLICE_BYTE)

15.2 网关消息路由流程

sequenceDiagram
    participant C as 客户端
    participant RH as XRouterHandle
    participant AP as XAuthProxy
    participant SP as XServiceProxy
    participant SPC as XServiceProxyClient
    participant BS as 后端服务

    C->>RH: 消息到达 ReadCB()
    RH->>AP: XAuthProxy::CheckToken(head)
    alt MSG_LOGIN_REQ (免鉴权)
        RH-->>RH: 跳过Token验证
    else 其他消息
        alt Token无效
            AP-->>RH: return false
            RH-->>RH: 丢弃消息
        else Token有效
            AP-->>RH: return true
        end
    end

    RH->>SP: XServiceProxy::SendMsg(head, msg, this)
    SP->>SP: 根据 head.service_name() 查找客户端列表
    SP->>SP: round-robin 选择可用连接

    alt MSG_GET_OUT_SERVICE_REQ
        SP->>SP: 返回可发现服务的列表
        SP-->>RH: ev->SendMsg(响应)
    else 普通业务消息
        SP->>SPC: client->SendMsg(head, msg, ev)
        SPC->>SPC: RegEvent(ev) → msg_id=(long long)ev
        SPC->>BS: XMsgEvent::SendMsg(head, msg)

        BS-->>SPC: 业务响应
        SPC->>SPC: ReadCB() → callback_task_.find(msg_id)
        SPC->>RH: router->second->SendMsg(head, msg)
        RH-->>C: 响应返回客户端
    end

各组件详解

XRouterServer： 网关主服务，CreateServiceHandle() 从配置中心读取 SSL 配置(crt/key/ca)，按需初始化 XSSLCtx，创建 XRouterHandle 实例。默认端口 API_GATEWAY_PORT(20010)。

XRouterHandle：
- ReadCB()： 入口函数，先通过 XAuthProxy::CheckToken() 鉴权(MSG_LOGIN_REQ 免鉴权) → 设置 msg_id = (long long)this → 转发给 XServiceProxy::SendMsg()
- Close()： 调用 XServiceProxy::DelEvent() 清理回调映射
- SendMsg()(重载)： 用于 XServiceProxyClient 回调将响应发送回客户端

XServiceProxy (单例，核心路由引擎)：
- client_map_: map<service_name, vector<XServiceProxyClient*>> 管理所有后端服务的代理连接
- SendMsg()： 根据 service_name 定位连接列表 → round-robin 选择可用(is_connected)连接 → 记录 ev→client 映射 → 转发消息。特殊处理 MSG_GET_OUT_SERVICE_REQ 返回可发现(is_find=true)的服务列表
- Main() (独立线程)： 每3秒从注册中心拉取最新服务列表 → 对比 client_map_ → 发现新服务实例时动态创建 XServiceProxyClient 并连接 → 对已断开的连接自动调用 Connect()
- DelEvent()： 清理 callbacks_ 中的 ev→client 映射(连接断开时调用)

XServiceProxyClient：
- Create(service_name)： 工厂方法，对 AUTH_NAME 返回 XAuthProxy 子类
- SendMsg()： RegEvent(ev) 记录 msg_id=指针值→ev 的映射，再通过父类 XMsgEvent::SendMsg 发送
- ReadCB()： 收到后端响应 → callback_task_.find(head->msg_id()) → 找到对应的 XRouterHandle → router->SendMsg() 将响应路由回客户端
- RegEvent/DelEvent： 管理 callback_task_ 映射表(线程安全，XMutable锁)

XAuthProxy (继承 XServiceProxyClient)：
- InitAuth()： 启动 TokenThread 后台线程，每秒遍历 token_cache 清理过期 token
- CheckToken(head)： 从本地 token_cache 查找 token → 验证 username 和 rolename 一致性 → 返回 true/false
- ReadCB()： 拦截 MSG_LOGIN_RES 响应 → 提取 token 信息存入 token_cache → 调用父类 ReadCB 继续转发

网关启动流程 (ms_gateway.cpp)

main():
 1. 解析命令行参数(port, register_ip, register_port)
 2. XAuthProxy::InitAuth() — 启动token缓存清理线程

GetDirReq()： 通过 SendMsg(GET_DIR_REQ) 发送目录请求，记录 cur_dir_ 用于后续刷新
GetDirRes()： 解析 XFileInfoList → XFileManager::Instance()->RefreshData() → 同时触发 GetService() + GetDiskInfoReq()
DeleteFileReq()： 发送 DELETE_FILE_REQ → DeleteFileRes() 自动重新 GetDirReq() 刷新
NewDirReq()： 发送 NEW_DIR_REQ → NewDirRes() 自动重新 GetDirReq() 刷新
GetService()： 发送 MSG_GET_OUT_SERVICE_REQ 获取上传/下载服务器列表 → GetServiceRes() 更新到 XFileManager
GetDiskInfoReq()： 发送 GET_DISK_INFO_REQ → GetDiskInfoRes() 刷新磁盘空间显示

17.3 XMSFileManager (客户端业务协调层)

InitFileManager()： 注册 XGetDir/XUpload/XDownload 三类消息回调 → 连接网关
UploadFile()： 从 download_servers() 轮询选择一个上传服务器 → 创建 XUploadClient 对象 → set_file() 加载文件并计算MD5 → StartConnect() 异步连接 → AddUploadTask() 记录任务
DownloadFile()： 从 upload_servers() 轮询选择一个下载服务器 → 创建 XDownloadClient 对象 → set_file() → StartConnect() 异步连接
set_login()： 设置XGetDirClient的登录信息(自动注入token/username到请求头)

十八、其他模块

18.1 XRegisterClient (注册中心客户端)

RegisterServer()： 保存服务名/IP/端口 → 设置自动重连+心跳定时器(3s) → StartConnect() → 连接成功后 ConnectedCB() 发送 MSG_REGISTER_REQ
GetServiceReq()： 发送 MSG_GET_SERVICE_REQ(ALL或ONE类型) 获取服务列表
GetServiceRes()： 解析 XServiceMap → 更新内存缓存 → 持久化到磁盘文件 "register_{name}{ip}{port}.cache"
GetServcies(阻塞版)： 等待连接成功 → 发送请求 → 轮询等待缓存结果 → 超时则尝试加载本地磁盘缓存
TimerCB()： 每3秒发送 MSG_HEART_REQ 心跳

18.2 XLogClient (日志客户端)

AddLog()： 格式化日志(时间+级别+文件+行号+内容) → 控制台输出/本地文件 → 加入 logs_ 队列
TimerCB() (每100ms)： 批量发送队列中的日志到日志服务器
LOGDEBUG/LOGINFO/LOGERROR/LOGFATAL 宏： 自动传入 __FILE__ 和 __LINE__

18.3 XConfigClient (配置客户端)

StartGetConf()： 连接配置中心 → WaitConnected() → LoadConfig(ip, port) → 设置定时器(3s) → 定时拉取配置
LoadConfigRes()： 解析配置 → 存入 conf_map(ip_port→XConfig) → 匹配本地配置则更新 cur_service_conf 并持久化到 "{port}_conf.cache"
LoadProto()： 使用 protobuf Importer + DynamicMessageFactory 动态加载 .proto 文件，反射生成 Message 对象(用于配置编辑器的动态解析)
GetInt/GetBool/GetString： 通过 protobuf 反射从 cur_service_conf 读取字段
